# Déploiements gérés

Un déploiement géré exécute votre [worker de workflows](/studio/workflows/getting-started/core_concepts/workers) pour vous. Vous indiquez un dépôt GitHub à Mistral. Mistral Cloud construit une image Docker à partir du `Dockerfile` du dépôt et exécute le conteneur. Vous ne gérez jamais de serveurs, et vous ne créez pas de clé API pour le worker.

:::info
Les déploiements gérés sont en version préliminaire publique. La fonctionnalité et ses limites peuvent évoluer.
:::

- [Premiers pas](/studio/workflows/managing-workflows-in-production/managed-deployments/getting-started) — scaffoldez l'application de démarrage, poussez-la sur GitHub et déployez-la.
- [Comment ça marche](/studio/workflows/managing-workflows-in-production/managed-deployments/how-it-works) — authentification par compte de service, entrypoint du Dockerfile et variables d'environnement injectées.
- [Secrets](/studio/workflows/managing-workflows-in-production/managed-deployments/secrets) — liez des secrets de l'espace de travail au déploiement, au build et à l'exécution.
- [Quotas](/studio/workflows/managing-workflows-in-production/managed-deployments/quotas) — plafonds de déploiements simultanés par plan.
- [Résolution des problèmes](/studio/workflows/managing-workflows-in-production/managed-deployments/troubleshooting) — tester l'image en local, et pannes courantes.

Un déploiement géré peut être [sécurisé](/studio/workflows/managing-workflows-in-production/hardened_deployments) : la sécurisation restreint l'enregistrement des workflows à certains utilisateurs et comptes de service.
