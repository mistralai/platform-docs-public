# Managed deployments

A managed deployment runs your [workflow worker](/studio/workflows/getting-started/core_concepts/workers) for you. You point Mistral at a GitHub repository. Mistral Cloud builds a Docker image from the repository's `Dockerfile` and runs the container. You never manage servers, and you do not create an API key for the worker.

:::info
Managed deployments are in public preview. The feature and its limits may change.
:::

- [Getting started](/studio/workflows/managing-workflows-in-production/managed-deployments/getting-started) — scaffold the starter app, push it to GitHub, and deploy it.
- [How it works](/studio/workflows/managing-workflows-in-production/managed-deployments/how-it-works) — service account authentication, Dockerfile entrypoint, and injected environment variables.
- [Secrets](/studio/workflows/managing-workflows-in-production/managed-deployments/secrets) — bind workspace secrets to the deployment, at build and at runtime.
- [Quotas](/studio/workflows/managing-workflows-in-production/managed-deployments/quotas) — concurrent deployment caps per plan.
- [Troubleshooting](/studio/workflows/managing-workflows-in-production/managed-deployments/troubleshooting) — test the image locally, and common failures.

A managed deployment can be [hardened](/studio/workflows/managing-workflows-in-production/hardened_deployments): hardening restricts workflow registration to selected users and service accounts.
