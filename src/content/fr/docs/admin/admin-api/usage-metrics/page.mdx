# Métriques d’utilisation avec l’API Admin

L’API Admin expose deux types de données de consommation :

- **Données de facturation** : coût et consommation de votre Organisation sur une période de facturation.
- **Données d’utilisation des produits** : activité dans le Chat et métriques d’utilisation de Vibe Code sur une période.

<SectionTab as="h1" sectionId="before-you-start">Avant de commencer</SectionTab>

Vous avez besoin d’une clé API Admin créée dans le Backoffice. Chaque requête utilise l’URL de base `https://console.mistral.ai/api/admin` et l’en-tête `x-api-key`. Consultez [Authentification de l’API Admin](/admin/admin-api/authentication).

<SectionTab as="h1" sectionId="billing-usage">Données de facturation</SectionTab>

Consultez le coût et la consommation de l’Organisation. Les paramètres `month`, `year` et `workspace_id` sont facultatifs. `month` et `year` sont des nombres entiers. Vous pouvez donc utiliser `5` ou `05`.

```bash
curl "https://console.mistral.ai/api/admin/usage?month=5&year=2026" \
  -H "x-api-key: $ADMIN_API_KEY"
```

La réponse ventile la consommation par catégorie (`chat`, `completion`, `ocr`, `audio`, `connectors`, `libraries_api`, `fine_tuning` et `vibe_usage`). Elle inclut aussi la période (`start_date`, `end_date`) et la devise (`currency`).

<SectionTab as="h1" sectionId="limits">Limites de dépenses et de débit</SectionTab>

Consultez les limites actuelles de l’Organisation :

```bash
# Limites de dépenses
curl https://console.mistral.ai/api/admin/spend-limit \
  -H "x-api-key: $ADMIN_API_KEY"

# Limites de débit (requêtes par seconde et limites de tokens par modèle)
curl https://console.mistral.ai/api/admin/rate-limit \
  -H "x-api-key: $ADMIN_API_KEY"
```

Définissez la limite de dépenses mensuelle de l’Organisation :

```bash
curl -X POST https://console.mistral.ai/api/admin/spend-limit \
  -H "Content-Type: application/json" \
  -H "x-api-key: $ADMIN_API_KEY" \
  -d '{"amount": 500, "no_monthly_limit": false}'
```

- `amount` : limite mensuelle, sous forme de nombre entier dans la devise de facturation de votre Organisation. `500` signifie 500, pas 500 centimes.
- `no_monthly_limit` : définissez cette valeur sur `true` pour retirer le plafond.

Pour en savoir plus sur les limites, consultez [Limites d’utilisation](/admin/billing-usage/usage-limits).

<SectionTab as="h1" sectionId="lechat-analytics">Données d’utilisation dans le Chat</SectionTab>

Les endpoints `/analytics/lechat` fournissent les données d’activité de la messagerie dans le Chat. Ils acceptent tous `start_time` et `end_time` sous forme d’horodatages Unix en secondes.

<SectionTab as="h2" variant="secondary" sectionId="lechat-by-user">Par utilisateur</SectionTab>

```bash
curl "https://console.mistral.ai/api/admin/analytics/lechat/usage/by_user_stats?start_time=1704067200&end_time=1706745600" \
  -H "x-api-key: $ADMIN_API_KEY"
```

La réponse indique, pour chaque utilisateur, le nombre de messages, de fichiers, d’images et de feuilles de calcul. Elle inclut aussi le nombre de conversations et d’agents distincts, les messages envoyés aux agents et l’horodatage du dernier message.

<SectionTab as="h2" variant="secondary" sectionId="lechat-by-agent">Par agent</SectionTab>

```bash
curl "https://console.mistral.ai/api/admin/analytics/lechat/usage/by_agent_stats?start_time=1704067200&end_time=1706745600" \
  -H "x-api-key: $ADMIN_API_KEY"
```

La réponse reprend les mêmes indicateurs d’activité, regroupés par agent, et inclut le nombre d’utilisateurs distincts par agent.

<SectionTab as="h2" variant="secondary" sectionId="lechat-by-time">Dans le temps</SectionTab>

Ajoutez `granularity` (`hour`, `day`, `week` ou `month`) pour regrouper les résultats.

```bash
curl "https://console.mistral.ai/api/admin/analytics/lechat/usage/by_time_stats?start_time=1704067200&end_time=1706745600&granularity=day" \
  -H "x-api-key: $ADMIN_API_KEY"
```

La réponse regroupe les indicateurs d’activité par intervalle, avec les utilisateurs et les agents distincts.

<SectionTab as="h1" sectionId="vibe-code-analytics">Données d’utilisation de Vibe Code</SectionTab>

Les endpoints `/analytics/vibe` fournissent les données d’activité de Vibe Code. Ils acceptent `start_time` et `end_time` sous forme d’horodatages Unix en secondes.

<SectionTab as="h2" variant="secondary" sectionId="vibe-by-workspace">Par espace de travail</SectionTab>

Transmettez `workspace_id` pour limiter le rapport à un seul espace de travail, ou omettez-le pour tous les espaces de travail.

```bash
curl "https://console.mistral.ai/api/admin/analytics/vibe/usage/by_workspace?start_time=1704067200&end_time=1706745600" \
  -H "x-api-key: $ADMIN_API_KEY"
```

La réponse fournit des séries quotidiennes pour les sessions (CLI, ACP et API), les utilisateurs actifs, les tokens consommés (entrée, sortie et cache, par modèle), les appels d’outils et les durées de session.

<SectionTab as="h2" variant="secondary" sectionId="vibe-by-organization">Par Organisation</SectionTab>

```bash
curl "https://console.mistral.ai/api/admin/analytics/vibe/usage/by_organization?start_time=1704067200&end_time=1706745600" \
  -H "x-api-key: $ADMIN_API_KEY"
```

La réponse fournit des séries quotidiennes pour les suggestions `next_edit` par résultat, les utilisateurs actifs `next_edit` et les lignes de code modifiées.
