# Compétences

Les compétences sont des **ensembles d'instructions réutilisables** qui enrichissent Vibe Code avec de nouveaux workflows et des commandes slash personnalisées. Vibe suit la [spécification Agent Skills](https://agentskills.io/specification), ce qui rend les compétences créées ici interopérables avec d'autres agents utilisant le même standard.

<SectionTab as="h2" sectionId="skill-format">Format d’une compétence</SectionTab>

Une compétence est un **répertoire contenant un fichier `SKILL.md`**. Ce fichier commence par un frontmatter YAML, suivi des instructions de la compétence en Markdown.

```markdown
---
name: code-review
description: Perform automated code reviews.
license: MIT
compatibility: Requires git
user-invocable: true
allowed-tools:
  - read_file
  - ask_user_question
---

# Code review skill

This skill helps analyze code quality and suggest improvements.
```

Champs courants du frontmatter :

- **`name`** : sert à invoquer la compétence.
- **`description`** : affiché dans la liste des compétences. Jusqu'à 1 024 caractères.
- **`user-invocable`** : lorsque la valeur est `true` (par défaut), rend la compétence accessible comme commande slash dans le CLI et l'extension VS Code. Définissez à `false` pour la masquer du sélecteur slash. L'agent peut toujours la charger.
- **`disable-model-invocation`** : définissez à `true` pour empêcher l'agent de charger la compétence de sa propre initiative. Vous pouvez toujours l'exécuter avec `/skill-name`.
- **`allowed-tools`** : liste les outils que la compétence compte utiliser. Vibe lit ce champ, mais ne l'applique pas : une compétence peut appeler n'importe quel outil autorisé par l'agent actif.

<SectionTab as="h2" sectionId="locations">Emplacements des compétences</SectionTab>

Le CLI découvre les compétences à plusieurs emplacements, dans l’ordre :

1. **Chemins personnalisés** définis dans `config.toml` → `skill_paths = ["/path/to/custom/skills"]`
2. Compétences **au niveau du projet** dans `./.vibe/skills/` ou `./.agents/skills/` lorsque le répertoire courant est [approuvé](/vibe/code/safety-approvals-permissions#trusted-folders).
3. Compétences **au niveau utilisateur** dans `~/.vibe/skills/` ou `~/.agents/skills/`.

<SectionTab as="h2" sectionId="filtering">Activer, désactiver ou filtrer les compétences</SectionTab>

Utilisez des modèles pour contrôler le chargement des compétences :

```toml
enabled_skills = ["code-review", "test-*"]
disabled_skills = ["experimental-*"]
```

Les filtres de compétences prennent en charge les **noms exacts**, les **glob patterns** et les **expressions régulières** avec le préfixe `re:`, comme les filtres d’outils. Si `enabled_skills` n’est pas vide, il sert de liste d’autorisation ; sinon toutes les compétences détectées sont disponibles, moins celles correspondantes à `disabled_skills`.

<SectionTab as="h2" sectionId="slash-commands">Commandes slash personnalisées</SectionTab>

L’ajout de commandes slash personnalisées passe idéalement par les compétences. `user-invocable` étant `true` par défaut, le nom de la compétence est accessible avec l’autocomplétion `/nom-compétence` dans le prompt CLI, ainsi que dans le sélecteur slash de [l’extension VS Code](/vibe/code/vs-code-extension/commands-slash-commands#slash-commands).

Saisissez `/skill-name` suivi de votre demande, par exemple `/code-review focus on error handling`. Vibe ajoute les instructions de la compétence à votre message.

<SectionTab as="h2" sectionId="plugins">Plugins</SectionTab>

Les [plugins](/vibe/code/cli/plugins) sont des paquets qui regroupent des compétences et d'autres extensions, comme des serveurs MCP, des hooks et des sous-agents. Vibe les charge depuis `~/.vibe/plugins/` et, dans les dossiers approuvés, depuis `./.vibe/plugins/`. Vibe préfixe les compétences des plugins avec l'espace de noms du plugin, par exemple `/vibe:skill-creator`. Exécutez `/plugins` pour lister les plugins de votre session, et `/reload-plugins` pour prendre en compte les modifications.

<SectionTab as="h2" sectionId="stay-in-control">Gardez le contrôle</SectionTab>

- **Examinez une compétence avant de l’activer** si elle peut invoquer des outils ayant des droits d’écriture.
- Pour limiter ce qu'une compétence peut faire, **restreignez les outils et les autorisations de l'agent**. `allowed-tools` ne restreint rien.
- Placez les compétences spécifiques au projet dans `./.vibe/skills/` pour que vos collaborateurs puissent les relire lors des revues de code.
