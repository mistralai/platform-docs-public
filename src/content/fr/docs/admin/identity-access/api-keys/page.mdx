# Clés API

Les clés API authentifient les requêtes vers l’API Mistral et d’autres outils Mistral. Dans Admin, les administrateurs Organisation peuvent créer, consulter, renouveler et supprimer des clés API dans les espaces de travail.

Les développeurs peuvent créer et gérer leurs propres clés API depuis la fenêtre `User Profile` dans Studio. Les utilisateurs qui utilisent uniquement Vibe n’ont généralement pas besoin de clés API, sauf s’ils utilisent aussi Studio, l’API, Vibe Code ou un autre outil développeur.

<SectionTab as="h1" sectionId="key-types">Types de clé API</SectionTab>

Les clés API peuvent être associées à différents produits :

| Type | Utilisation |
| --- | --- |
| **Studio** | Clés API standard pour utiliser l’API Mistral. |
| **Vibe** | Clés utilisées par Vibe Code. |
| **Mistral Code** | Clés héritées pour l’ancienne offre Mistral Code. |

<SectionTab as="h1" sectionId="create-key-admin">Créer une clé API en tant qu’administrateur</SectionTab>

1. Ouvrez <AppLink href="https://admin.mistral.ai/plateforme/api-keys" path={["Panneau d’administration", "API", "API Keys"]} />.
2. Cliquez sur `Create new key`.
3. Si nécessaire, saisissez un `Key name`.
4. Sélectionnez le `Workspace` auquel la clé appartient.
5. Si nécessaire, définissez une date d’`Expiration`. Utilisez `No expiration date` pour une clé qui n’expire pas automatiquement.
6. Choisissez le **périmètre d’accès aux Connecteurs**.
7. Cliquez sur `Create new key`.
8. Copiez la clé immédiatement.

Après avoir créé une clé, vous **ne pouvez pas modifier** son espace de travail, son périmètre d’accès aux Connecteurs ou sa date d’expiration. Pour modifier ces paramètres, créez une nouvelle clé et supprimez l’ancienne.

:::warning
Les clés API sont confidentielles et ne sont **pas partagées** dans votre Organisation. La clé complète est **affichée une seule fois**. Après avoir fermé la fenêtre, vous ne pouvez plus la récupérer. Stockez-la dans un gestionnaire de mots de passe ou un coffre de secrets. Ne la partagez pas et ne l’ajoutez pas au contrôle de version.
:::

<SectionTab as="h1" sectionId="manage-keys">Gérer les clés API</SectionTab>

Ouvrez <AppLink href="https://admin.mistral.ai/plateforme/api-keys" path={["Panneau d’administration", "API", "API Keys"]} /> pour consulter les clés API dans l’Organisation.

La liste des clés affiche :

- les clés actives et expirées ;
- le type de clé ;
- l’espace de travail ;
- la date de dernière utilisation ;
- la date d’expiration.

Depuis la liste des clés, les administrateurs peuvent :

- renouveler une clé en créant une nouvelle clé et en supprimant l’ancienne ;
- supprimer une clé ;
- identifier les clés inutilisées ou expirées.

<SectionTab as="h1" sectionId="user-profile-keys">Gérer vos propres clés API</SectionTab>

Les administrateurs et les développeurs peuvent gérer leurs propres clés API depuis la fenêtre `User Profile` :

- Dans Studio, ouvrez <AppLink href="https://console.mistral.ai/home?profile_dialog=api-keys" path={["Studio", "API keys"]} />.
- Ou ouvrez le menu de votre profil utilisateur et sélectionnez `API Keys`.

Utilisez cette méthode pour les clés que vous possédez. Utilisez la méthode du Panneau Admin lorsque vous devez gérer les clés dans toute l’Organisation.

:::tip
Les administrateurs peuvent aussi consulter les clés API depuis le panneau `Détails de l’utilisateur` d’un membre. L’onglet `API Keys` affiche les clés du membre, leur type, l’espace de travail auquel chaque clé appartient, leur date de dernière utilisation et leur date d’expiration. Consultez [Gestion des utilisateurs](/admin/identity-access/user-management#api-keys).
:::

<SectionTab as="h1" sectionId="api-key-scope">Périmètre des clés API</SectionTab>

Les clés API sont rattachées à l’espace de travail dans lequel elles ont été créées. Les requêtes envoyées avec une clé utilisent le quota, les limites de débit et les ressources de cet espace de travail.

Pour utiliser différentes clés pour différents environnements, comme le développement, la préproduction et la production, créez des [espaces de travail](/admin/workspaces/your-first-workspace) séparés et créez une clé API dédiée dans chaque espace de travail.

Le périmètre d’accès aux Connecteurs contrôle les Connecteurs d’espace de travail que la clé peut utiliser.

| Périmètre | Accès |
| --- | --- |
| **Connecteurs partagés uniquement** | Accès uniquement aux Connecteurs partagés avec l’espace de travail, pas aux Connecteurs privés. |
| **Connecteurs privés et partagés** | Accès aux Connecteurs privés détenus par le créateur de la clé et aux Connecteurs partagés avec l’espace de travail. |

Le périmètre par défaut est **Connecteurs partagés uniquement**. Utilisez-le pour l’automatisation. Choisissez **Connecteurs privés et partagés** uniquement lorsque l’application a besoin de Connecteurs privés détenus par le créateur de la clé.

Pour l’administration des Connecteurs, consultez [Connecteurs](/admin/identity-access/connectors).

:::note
Les clés API ne sont pas associées à des offres. Vous **ne pouvez pas** créer une clé API gratuite ou une clé API Scale. Chaque clé utilise automatiquement l’offre souscrite par votre Organisation. Consultez [Abonnements](/admin/billing-usage/subscriptions).
:::
