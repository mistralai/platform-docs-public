# Secrets Manager

Secrets Manager stores credentials such as API keys, tokens, and connection strings, and lets your agents, workflows, and apps read them at runtime without hardcoding them.

Secrets are scoped to a workspace and shared by its members. Access is checked on every request, and each secret keeps a version history so you can roll the value forward to a new version or restore a previous one.

:::info
Secrets Manager is in public preview. Behavior and limits may change.
:::

<SectionTab as="h1" sectionId="before-you-begin">Before you begin</SectionTab>

- Workspace members can create, update, and delete secrets in their workspace.
- Use lowercase secret names. A name is unique within the workspace.

<SectionTab as="h1" sectionId="create">Create a secret</SectionTab>

1. Open <AppLink href="https://console.mistral.ai/secrets" path={["Studio", "Secrets"]} />.
2. Select `Create secrets`.
3. Enter a `Name`.
4. Enter the `Value`.
5. Optionally add a `Description`.
6. Select `Create secrets`.

The value is stored as the first version of the secret. It is not shown again after you create it.

<SectionTab as="h1" sectionId="manage">Manage secrets</SectionTab>

From the list, you can search by name and open a secret's actions menu to:

- **Edit** the description, or set a new value. Setting a new value creates a new version; earlier versions are retained.
- **Delete** the secret. Delete is a soft delete: the secret stops resolving but remains recoverable.

To recover a deleted secret, open `More actions`, select `View deleted secrets`, then select `Restore` on the secret you want back.

<SectionTab as="h1" sectionId="values">Secret values are write-only</SectionTab>

The console never displays a stored value. After you create a secret or set a new value, the value is masked and cannot be read back through the console.

:::warning
Keep your own copy of a value if you need it elsewhere. To change a value, set a new one, which creates a new version. Do not commit secret values to version control.
:::

<SectionTab as="h1" sectionId="reference">Reference secrets from workloads</SectionTab>

Managed deployments read secrets at runtime by reference, so a value never has to be embedded in your code or configuration. Bind a secret to a deployment in the console; the deployment's configuration stores the reference, and the value is resolved when the workload starts.

A reference has the form `secret:workspace:<name>`, set as an environment variable on the deployment:

```
THIRD_PARTY_API_KEY = secret:workspace:third_party_api_key
```

When the workload starts, the platform resolves the reference and injects the value into that environment variable. Resolution uses the workload's own identity, so a workload can only read secrets in its own workspace.

<SectionTab as="h1" sectionId="rotate">Rotate a secret</SectionTab>

To rotate a secret, set a new value, then restart the deployments that use it. A running workload keeps the value it started with until it restarts and resolves the reference again.
