# Transcription de fichiers

La transcription de fichiers transforme un enregistrement dont vous disposez déjà — un appel, une réunion ou un épisode de podcast — en texte grâce à une seule requête. Cette page explique comment envoyer l'audio, quels champs de la requête modifient le résultat et comment obtenir des horodatages ou une réponse en streaming.

<CtaButton href="/api/endpoint/audio/transcriptions#operation-audio_api_v1_transcriptions_post">Référence API — POST /v1/audio/transcriptions</CtaButton>

:::info
La transcription de fichiers est le mode hors ligne : l'enregistrement complet existe avant son envoi. Pour un audio encore en cours d'enregistrement, comme un microphone ou une ligne téléphonique, utilisez [Transcription en temps réel](/studio/audio/speech-to-text/transcribe-in-realtime). [Audio hors ligne et en temps réel](/studio/audio/concepts/offline-and-realtime) explique la différence entre les deux modes.
:::

<SectionTab as="h2" sectionId="choose-input">Choisir votre source audio</SectionTab>

L'audio parvient à l'API de trois manières, et chaque requête en utilise exactement une :

| Entrée | Champ | Quand l'utiliser |
| --- | --- | --- |
| Fichier audio | `file` | L'enregistrement se trouve sur votre machine ou votre serveur. |
| URL audio | `file_url` | L'enregistrement est déjà hébergé à une URL accessible par l'API. |
| Fichier téléchargé | `file_id` | Vous avez téléchargé l'enregistrement sur l'API Files avec `purpose=audio`, par exemple pour le transcrire plusieurs fois. |

Chaque onglet n'affiche que la partie de la requête qui change. Le reste de la requête est le même que dans [Effectuer une requête et lire le résultat](#make-a-request).

<Tabs groupId="input">
  <TabItem value="file" label="Fichier audio" default>

```bash
  -F file=@obama.mp3
```

  </TabItem>
  <TabItem value="url" label="URL audio">

```bash
  -F file_url=https://docs.mistral.ai/audio/obama.mp3
```

  </TabItem>
  <TabItem value="uploaded" label="ID de fichier téléchargé">

```bash
# Upload the file once with purpose=audio, then pass the returned id
curl https://api.mistral.ai/v1/files \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -F purpose=audio \
  -F file=@obama.mp3

  -F file_id=$FILE_ID
```

  </TabItem>
</Tabs>

:::tip
Quand vous n'avez plus besoin d'un enregistrement téléchargé, supprimez-le avec `DELETE /v1/files/{file_id}`.
:::

Pour connaître les formats audio acceptés et la taille maximale des fichiers, voir [Formats audio](/studio/audio/specs-and-limits/audio-formats) et [Limites](/studio/audio/specs-and-limits/limits).

<SectionTab as="h2" sectionId="make-a-request">Envoyer une requête et lire le résultat</SectionTab>

Cette requête envoie un enregistrement local d'un appel d'assistance et renvoie sa transcription :

<Tabs groupId="code">
  <TabItem value="curl" label="curl" default>

```bash
curl https://api.mistral.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -F model=voxtral-mini-transcribe-3 \
  -F file=@customer_call.wav
```

  </TabItem>
  <TabItem value="python" label="python">

```python
import os

from mistralai.client import Mistral

client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])

with open("customer_call.wav", "rb") as audio:
    transcription = client.audio.transcriptions.complete(
        model="voxtral-mini-transcribe-3",
        file={"file_name": "customer_call.wav", "content": audio},
    )

print(transcription.model_dump_json(indent=2))
```

  </TabItem>
  <TabItem value="typescript" label="typescript">

```typescript
import { readFile } from "node:fs/promises";

import { Mistral } from "@mistralai/mistralai";

const client = new Mistral({ apiKey: process.env.MISTRAL_API_KEY });

const transcription = await client.audio.transcriptions.complete({
  model: "voxtral-mini-transcribe-3",
  file: { fileName: "customer_call.wav", content: await readFile("customer_call.wav") },
});

console.log(JSON.stringify(transcription, null, 2));
```

  </TabItem>
</Tabs>

La réponse contient la transcription complète dans `text` :

```json
{
  "model": "voxtral-mini-transcribe-3",
  "text": "Thanks for calling Northwind Support. This is Daniel. How can I help you today? Hi Daniel. I ordered two Quilliera headsets last week. Order 4417. And the tracking page still says pending. [...] Of course. I will email the tracking link today and ask billing to issue the invoice by Friday. Perfect. Thank you.",
  "language": null,
  "segments": [],
  "usage": {
    "prompt_audio_seconds": 34,
    "prompt_tokens": 3,
    "total_tokens": 879,
    "completion_tokens": 126,
    "prompt_tokens_details": {
      "cached_tokens": 1,
      "audio_tokens": 750
    },
    "service_tier": "standard"
  },
  "finish_reason": null
}
```

Les autres champs :

- `segments` reste vide, sauf si vous demandez des [horodatages](#timestamps).
- `language` vaut `null`, même lorsque vous fixez la langue. Pour obtenir la langue détectée dans la réponse lorsque vous ne la fixez pas, définissez `return_language` sur `true`.
- `usage.prompt_audio_seconds` correspond à la durée de l'audio traité par le modèle, exprimée en secondes.

<SectionTab as="h3" variant="secondary" sectionId="request-fields">Champs utiles pour la requête</SectionTab>

Ces champs modifient le résultat renvoyé. Envoyez-les sous forme de champs de formulaire multipart. Pour la liste complète des champs, voir la [Référence API](/api/endpoint/audio/transcriptions#operation-audio_api_v1_transcriptions_post).

| Champ | Rôle | Détails |
| --- | --- | --- |
| `model` | Obligatoire. `voxtral-mini-transcribe-3` ou `voxtral-small-transcribe-3`. | [Choisir votre modèle](/studio/audio/speech-to-text/overview#choose-your-model) |
| `file`, `file_url` ou `file_id` | L'audio à transcrire. Envoyez exactement un seul de ces champs. | [Choisir votre entrée audio](#choose-input) |
| `language` | La langue de l'audio, sous forme de code à deux lettres comme `fr`. Omettez-le pour laisser le modèle la détecter. | [Fixer la langue](#pin-the-language) |
| `timestamp_granularities` | Définissez-le sur `segment` pour obtenir chaque segment de la transcription avec ses temps de début et de fin. Omettez-le pour n'obtenir que le texte. Les horodatages au niveau du mot ne sont pas disponibles. | [Horodatages](#timestamps) |
| `diarize` | Définissez-le sur `true` pour étiqueter chaque segment avec son locuteur. Nécessite `timestamp_granularities=segment`. | [Diariser les locuteurs](/studio/audio/speech-to-text/diarize-speakers) |
| `context_bias` | Des noms et des termes que le modèle doit orthographier correctement, ou une phrase qui décrit l'enregistrement. Répétez le champ une fois par entrée. [Vocabulaire personnalisé](/studio/audio/concepts/custom-vocabulary) explique quand il est utile. | [Biais de contexte et de vocabulaire](/studio/audio/speech-to-text/bias-context-and-vocabulary) |
| `stream` | Définissez-le sur `true` pour recevoir la transcription par fragments sous forme d'événements envoyés par le serveur. | [Recevoir la réponse en streaming](#stream-the-response) |

<SectionTab as="h3" variant="secondary" sectionId="pin-the-language">Définir la langue</SectionTab>

Par défaut, le modèle détecte la langue de l'enregistrement. Si vous la connaissez à l'avance, transmettez-la dans `language` sous forme de code ISO 639-1 à deux lettres :

```bash
curl https://api.mistral.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -F model=voxtral-mini-transcribe-3 \
  -F file=@meeting_fr.wav \
  -F language=fr
```

Fixer la langue peut améliorer la précision. Omettez-la quand la langue peut varier d'un enregistrement à l'autre. Pour les langues prises en charge et leurs codes, voir [Langues](/studio/audio/specs-and-limits/languages).

<SectionTab as="h2" sectionId="timestamps">Horodatages</SectionTab>

Les horodatages des segments indiquent le moment où chaque partie de la transcription a été prononcée. Vous en avez besoin pour les sous-titres, pour les étiquettes de locuteurs et pour accéder directement à un moment de l'enregistrement. Ajoutez `timestamp_granularities=segment` à la requête :

```bash
curl https://api.mistral.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -F model=voxtral-mini-transcribe-3 \
  -F file=@customer_call.wav \
  -F timestamp_granularities=segment
```

La réponse conserve le `text` complet et remplit `segments`. Les trois premiers segments sont les suivants :

```json
{
  "segments": [
    {
      "type": "transcription_segment",
      "text": "Thanks for calling Northwind Support.",
      "start": 0.0,
      "end": 1.6,
      "speaker_id": null
    },
    {
      "type": "transcription_segment",
      "text": " This is Daniel.",
      "start": 1.7,
      "end": 2.4,
      "speaker_id": null
    },
    {
      "type": "transcription_segment",
      "text": " How can I help you today?",
      "start": 2.6,
      "end": 3.5,
      "speaker_id": null
    }
  ]
}
```

Chaque segment contient :

- `text` : les mots du segment. Il conserve son espace initial, ce qui permet de réassembler les segments pour retrouver la transcription complète.
- `start` et `end` : la position du segment dans l'enregistrement, en secondes.
- `speaker_id` : `null`, sauf si vous définissez aussi `diarize`, voir [Diariser les locuteurs](/studio/audio/speech-to-text/diarize-speakers).

:::note
Les horodatages ne sont disponibles que par segment. Une requête d'horodatages au niveau du mot renvoie une erreur.
:::

<SectionTab as="h2" sectionId="stream-the-response">Diffuser la réponse en streaming</SectionTab>

Avec `stream=true`, l'API envoie la transcription par fragments au fur et à mesure de son écriture, ce qui permet à votre application d'afficher les premiers mots d'un enregistrement long sans attendre le résultat complet :

<Tabs groupId="code">
  <TabItem value="curl" label="curl" default>

```bash
curl -N https://api.mistral.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -F model=voxtral-mini-transcribe-3 \
  -F file=@customer_call.wav \
  -F stream=true
```

  </TabItem>
  <TabItem value="python" label="python">

```python
import os

from mistralai.client import Mistral

client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])

with open("customer_call.wav", "rb") as audio:
    with client.audio.transcriptions.stream(
        model="voxtral-mini-transcribe-3",
        file={"file_name": "customer_call.wav", "content": audio},
    ) as events:
        for event in events:
            if event.event == "transcription.text.delta":
                print(event.data.text, end="", flush=True)
            elif event.event == "transcription.done":
                print(f"\n\nDone: {event.data.usage.prompt_audio_seconds} s of audio")
```

  </TabItem>
  <TabItem value="typescript" label="typescript">

```typescript
import { readFile } from "node:fs/promises";

import { Mistral } from "@mistralai/mistralai";

const client = new Mistral({ apiKey: process.env.MISTRAL_API_KEY });

const events = await client.audio.transcriptions.stream({
  model: "voxtral-mini-transcribe-3",
  file: { fileName: "customer_call.wav", content: await readFile("customer_call.wav") },
});

for await (const event of events) {
  if (event.data.type === "transcription.text.delta") {
    process.stdout.write(event.data.text);
  } else if (event.data.type === "transcription.done") {
    console.log(`\n\nDone: ${event.data.usage.promptAudioSeconds} s of audio`);
  }
}
```

  </TabItem>
</Tabs>

Le flux est une série d'événements envoyés par le serveur :

```text
event: transcription.text.delta
data: {"type":"transcription.text.delta","text":"Thanks"}

event: transcription.text.delta
data: {"type":"transcription.text.delta","text":" for"}

...

event: transcription.done
data: {"model":"voxtral-mini-transcribe-3","text":"Thanks for calling Northwind Support. [...]","language":null,"segments":[],"usage":{"prompt_audio_seconds":34,...},"finish_reason":null,"type":"transcription.done"}
```

Pour le consommer :

1. Ajoutez le `text` de chaque événement `transcription.text.delta` à ce que vous affichez.
2. Quand vous recevez `transcription.done`, utilisez sa charge utile comme résultat final : elle contient les mêmes champs qu'une réponse sans streaming, y compris `usage`.

La référence API liste les autres types d'événements qu'un flux peut transporter : `transcription.language`, `transcription.segment.delta` (avec `speaker_id`, `start` et `end`) et `transcription.done`.

:::info
Le streaming n'accélère pas la transcription elle-même, et ce n'est pas de la transcription en temps réel : l'enregistrement complet est d'abord envoyé, et seul le résultat arrive par fragments. Voir [Latence](/studio/audio/concepts/latency#offline-requests).
:::

<SectionTab as="h2" sectionId="common-issues">Problèmes courants</SectionTab>

Ces erreurs proviennent d'un champ de la requête. Corrigez le champ, puis envoyez à nouveau la requête :

| Erreur | Cause | Solution |
| --- | --- | --- |
| 400 `Word-level segments are not enabled for this model` | `timestamp_granularities=word` | Utilisez `segment`. |
| 422 quand vous définissez `diarize` | Diarisation sans horodatages de segments | Ajoutez `timestamp_granularities=segment`. |
| 422 `Invalid language alpha2 code` | `language` n'est pas un code à deux lettres | Utilisez un code de [Langues](/studio/audio/specs-and-limits/languages), comme `en` ou `fr`. |
| 400 `maximum context length` | Pris ensemble, l'audio et les entrées `context_bias` dépassent le contexte du modèle. Rien n'est tronqué : la requête échoue. | Raccourcissez la liste `context_bias`, voir [Biais de contexte et de vocabulaire](/studio/audio/speech-to-text/bias-context-and-vocabulary). |

:::tip
Pour les problèmes liés à la transcription elle-même, comme un audio bruité, des locuteurs qui parlent en même temps ou des noms mal orthographiés, voir [Dépannage de la reconnaissance vocale](/studio/audio/speech-to-text/troubleshooting).
:::
