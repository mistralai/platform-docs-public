# Speech generation

A speech request turns a complete text into an audio file in one call, in the voice and the format you choose. This page shows the request, the fields that change the result, and the errors you're most likely to meet.

:::info
To start playback before the whole file is ready, see [Stream speech](/studio/audio/text-to-speech/stream-speech). For how voices, tags, and instructions shape the result, see [Voices](/studio/audio/concepts/voices).
:::

<CtaButton href="/api/endpoint/audio/speech#operation-speech_v1_audio_speech_post">API reference — POST /v1/audio/speech</CtaButton>

<SectionTab as="h2" sectionId="make-a-request">Make a request and use the response</SectionTab>

Send the text and a voice in one `POST` request. The response carries the audio, base64-encoded, in `audio_data`: decode it and save it to a file.

<Tabs groupId="code">
  <TabItem value="curl" label="curl" default>

```bash
curl -s https://api.mistral.ai/v1/audio/speech \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "voxtral-mini-tts-3-0",
    "input": "Your order shipped this morning and should arrive on Thursday.",
    "voice_id": "gb_jane_neutral",
    "response_format": "mp3"
  }' | jq -r '.audio_data' | base64 --decode > order_update.mp3
```

  </TabItem>
  <TabItem value="python" label="python">

```python
import base64
import os
from pathlib import Path

from mistralai.client import Mistral

client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])

response = client.audio.speech.complete(
    model="voxtral-mini-tts-3-0",
    input="Your order shipped this morning and should arrive on Thursday.",
    voice_id="gb_jane_neutral",
    response_format="mp3",
)

audio = base64.b64decode(response.audio_data)
output = Path("order_update.mp3")
output.write_bytes(audio)
print(f"Saved {output.resolve()} ({len(audio)} bytes)")
```

  </TabItem>
  <TabItem value="typescript" label="typescript">

```typescript
import { writeFileSync } from "node:fs";
import { resolve } from "node:path";

import { Mistral } from "@mistralai/mistralai";

const client = new Mistral({ apiKey: process.env.MISTRAL_API_KEY });

const response = await client.audio.speech.complete({
  model: "voxtral-mini-tts-3-0",
  input: "Your order shipped this morning and should arrive on Thursday.",
  voiceId: "gb_jane_neutral",
  responseFormat: "mp3",
});

const audio = Buffer.from(response.audioData, "base64");
const output = resolve("order_update.mp3");
writeFileSync(output, audio);
console.log(`Saved ${output} (${audio.length} bytes)`);
```

  </TabItem>
</Tabs>

The examples save `order_update.mp3` in the current directory. Open it in any audio player to listen.

<SectionTab as="h3" variant="secondary" sectionId="request-fields">Request fields</SectionTab>

The following table lists the fields that most often change the result. For the full list, see the API reference.

| Field | What it does |
| --- | --- |
| `model` | The speech model, for example `voxtral-mini-tts-3-0`. |
| `input` | The text to speak. It can carry inline [emotion and pace tags](/studio/audio/text-to-speech/emotion-tags). |
| `voice_id` | The voice to use: a preset slug such as `gb_jane_neutral`, or the ID of a voice saved in your workspace. See [Voices](/studio/audio/text-to-speech/voices). |
| `ref_audio` | A short recording, base64-encoded, to clone a voice for this request only, instead of `voice_id`. See [Voice cloning](/studio/audio/text-to-speech/voice-cloning). |
| `response_format` | The audio format of the result. See [Response formats](#response-formats). |
| `expressiveness` |  See [Expressiveness](#expressiveness). |
| `instruction` | Style instructions are not available at launch. See [Style instructions](/studio/audio/text-to-speech/style-instructions). |
| `phoneme_hints` | The pronunciation of specific words, as lists of phonemes. See [Custom pronunciation](/studio/audio/text-to-speech/custom-pronunciation). |
| `stream` | Set to `true` to receive the audio in chunks as it's generated. See [Stream speech](/studio/audio/text-to-speech/stream-speech). |
| `conversation_history` | Prior conversation audio that conditions the delivery of the new response. See [Contextual TTS](#contextual-tts). |

<SectionTab as="h2" sectionId="response-formats">Response formats</SectionTab>

Set `response_format` to `mp3` (the default), `wav`, `pcm`, `flac`, or `opus`. To choose between them, see [Audio formats](/studio/audio/specs-and-limits/audio-formats).

<SectionTab as="h2" sectionId="expressiveness">Expressiveness</SectionTab>

`expressiveness` sets how strongly the generated speech follows what you ask for: the voice, the text, and any emotion tags or style instruction. It accepts values from `1.0` to `5.0`.

Controls how expressive the speech is. Higher values trade voice similarity and stability for stronger delivery. Start with the default, raise it if the emotion doesn't come through, and lower it if the speech sounds forced.

<SectionTab as="h2" sectionId="contextual-tts">Contextual TTS</SectionTab>

When the speech is part of a conversation, pass `conversation_history` to give the model the context it needs to adjust the delivery — tone, pacing, and emphasis — to match the flow of the conversation. The `voice_id` sets the voice and accent of the generated speech; the conversation history helps the model deliver the response in a way that fits what came before.

Without `conversation_history`, the model generates the response blind, with no sense of the prior conversation. This is fine for standalone messages (announcements, prompts, reading an article) but loses the conversational context that makes the delivery feel natural in a dialogue.

`conversation_history` is an array of turns, oldest first. Each turn is either a user turn with audio, or an assistant turn with text and audio. The new `input` is the assistant's reply to the last user turn in the history.

:::note
`conversation_history` requires a Voxtral 3 preset voice (`voice_id`), and cannot be combined with `ref_audio`, `instruction`, or `realtime_context`.
:::

The audio in each turn is base64-encoded. The history must be nonempty, alternate between `user` and `assistant`, and end with a `user` turn.

<Tabs groupId="code">
  <TabItem value="curl" label="curl" default>

```bash
curl -s https://api.mistral.ai/v1/audio/speech \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "voxtral-mini-tts-3-0",
    "voice_id": "voice_592",
    "input": "I'm sorry about the delay. Let me check that for you.",
    "response_format": "wav",
    "conversation_history": [
      {
        "role": "user",
        "audio": {
          "data": "<BASE64_USER_AUDIO_1>"
        }
      },
      {
        "role": "assistant",
        "text": "How can I help you today?",
        "audio": {
          "data": "<BASE64_ASSISTANT_AUDIO>"
        }
      },
      {
        "role": "user",
        "audio": {
          "data": "<BASE64_USER_AUDIO_2>"
        }
      }
    ]
  }' | jq -r '.audio_data' | base64 --decode > reply.wav
```

  </TabItem>
  <TabItem value="python" label="python">

```python
import base64
import os
from pathlib import Path

from mistralai.client import Mistral

client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])

user_audio_1 = base64.b64encode(Path("user_turn_1.wav").read_bytes()).decode()
assistant_audio = base64.b64encode(Path("assistant_turn.wav").read_bytes()).decode()
user_audio_2 = base64.b64encode(Path("user_turn_2.wav").read_bytes()).decode()

response = client.audio.speech.complete(
    model="voxtral-mini-tts-3-0",
    voice_id="voice_592",
    input="I'm sorry about the delay. Let me check that for you.",
    response_format="wav",
    additional_properties={
        "conversation_history": [
            {"role": "user", "audio": {"data": user_audio_1}},
            {"role": "assistant", "text": "How can I help you today?", "audio": {"data": assistant_audio}},
            {"role": "user", "audio": {"data": user_audio_2}},
        ]
    },
)

audio = base64.b64decode(response.audio_data)
Path("reply.wav").write_bytes(audio)
print(f"Saved reply.wav ({len(audio)} bytes)")
```

  </TabItem>
  <TabItem value="typescript" label="typescript">

```typescript
import { readFileSync, writeFileSync } from "node:fs";
import { resolve } from "node:path";

import { Mistral } from "@mistralai/mistralai";

const client = new Mistral({ apiKey: process.env.MISTRAL_API_KEY });

const userAudio1 = readFileSync("user_turn_1.wav").toString("base64");
const assistantAudio = readFileSync("assistant_turn.wav").toString("base64");
const userAudio2 = readFileSync("user_turn_2.wav").toString("base64");

const response = await client.audio.speech.complete({
  model: "voxtral-mini-tts-3-0",
  voiceId: "voice_592",
  input: "I'm sorry about the delay. Let me check that for you.",
  responseFormat: "wav",
  conversation_history: [
    { role: "user", audio: { data: userAudio1 } },
    { role: "assistant", text: "How can I help you today?", audio: { data: assistantAudio } },
    { role: "user", audio: { data: userAudio2 } },
  ],
});

const audio = Buffer.from(response.audioData, "base64");
writeFileSync(resolve("reply.wav"), audio);
console.log(`Saved reply.wav (${audio.length} bytes)`);
```

  </TabItem>
</Tabs>

Each turn requires `audio: { data: string }` with a base64-encoded audio file. Assistant turns also require `text`. The history must end with a `user` turn, and the new `input` is the assistant's reply to that final turn.

<SectionTab as="h2" sectionId="common-issues">Common issues</SectionTab>

These are the problems you're most likely to meet with a speech request. For the full list, see [Troubleshooting](/studio/audio/text-to-speech/troubleshooting).

| Symptom | Cause | Fix |
| --- | --- | --- |
| `404` error of type `invalid_voice`: `Voice 'x' not found.` | The voice slug or ID doesn't exist in the catalog or in your workspace. | List the voices and copy the exact slug or ID. See [Voices](/studio/audio/text-to-speech/voices). |
| `400` error: `Either ref_audio or voice must be provided.` | The request has no voice. | Add `voice_id`. |
| A name, a brand, or an acronym is mispronounced | The voice guesses the reading from the spelling. | Give the word its phonemes. See [Custom pronunciation](/studio/audio/text-to-speech/custom-pronunciation). |
