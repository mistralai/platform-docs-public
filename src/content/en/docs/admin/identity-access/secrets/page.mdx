# Secrets Manager

Secrets Manager stores credentials such as API keys, tokens, and connection strings, and lets your agents, workflows, and apps read them at runtime without hardcoding them.

Each secret is scoped to your organization, a workspace, or a user. Access is checked per request, and every secret keeps a version history so you can update or restore a value.

:::info
Secrets Manager is in public preview. Behavior and limits may change.
:::

<SectionTab as="h1" sectionId="scopes">Secret scopes</SectionTab>

A secret's scope controls who can read it and where it applies. Choose the narrowest scope that fits.

| Scope | Read access | Use it for |
| --- | --- | --- |
| **Workspace** | Members of the workspace | Credentials a team or an app shares within one workspace. |
| **User** | The individual user | Personal credentials, such as a user's own connector tokens. |
| **Organization** | All workspaces in the organization | Credentials shared across every workspace in the organization. |

In the console, workspace secrets appear under the `Workspace` tab and user secrets under the `My Secrets` tab. Organization secrets are managed through the API.

<SectionTab as="h1" sectionId="before-you-begin">Before you begin</SectionTab>

- You need permission to manage secrets in the scope you choose. Managing organization-wide secrets requires an Organization Admin role.
- A secret name is unique within its scope. Names are case-sensitive and identify the secret in both the console and the API.

<SectionTab as="h1" sectionId="create">Create a secret</SectionTab>

1. Open <AppLink href="https://console.mistral.ai/secrets" path={["Studio", "Secrets"]} />.
2. Select the `Workspace` or `My Secrets` tab, depending on the scope you want.
3. Select `Create secrets`.
4. Enter a `Name`.
5. Enter the `Value`.
6. Optionally add a `Description`.
7. Select `Create secrets`.

The value is stored as the first version of the secret. It is not shown again after you create it.

<SectionTab as="h1" sectionId="manage">Manage secrets</SectionTab>

From the list, you can search by name and open a secret's actions menu to:

- **Edit** the description, or set a new value. Setting a new value creates a new version; earlier versions are retained.
- **Delete** the secret. Delete is a soft delete: the secret stops resolving but remains recoverable.

To recover a deleted secret, open `More actions`, select `View deleted secrets`, then select `Restore` on the secret you want back.

<SectionTab as="h1" sectionId="values">Secret values are write-only</SectionTab>

The console never displays a stored value. After you create or update a secret, the value is masked and cannot be read back through the console.

:::warning
Keep your own copy of a value if you need it elsewhere. To change a value, set a new one, which creates a new version. Do not commit secret values to version control.
:::

<SectionTab as="h1" sectionId="reference">Reference secrets from workloads</SectionTab>

Your agents, workflows, and managed deployments reference a secret by its name and scope. The value is resolved at runtime using the workload's own identity, so the value never has to be embedded in your code or configuration.

Because resolution is scoped, a workload only reads secrets it is authorized for.

<SectionTab as="h1" sectionId="api">Use the API</SectionTab>

The base URL is `https://api.mistral.ai`. Authenticate with your Mistral API key. The path segment selects the scope:

| Action | Method and path |
| --- | --- |
| Create or update | `PUT /v1/secrets/{scope}/{id}/{name}` |
| Get metadata | `GET /v1/secrets/{scope}/{id}/{name}` |
| List | `GET /v1/secrets/{scope}/{id}` |
| Delete | `DELETE /v1/secrets/{scope}/{id}/{name}` |
| Restore | `POST /v1/secrets/{scope}/{id}/{name}/restore` |

`{scope}` is `workspaces`, `users`, or `orgs`, and `{id}` is the corresponding identifier.

Create a workspace secret:

```bash
curl -X PUT "https://api.mistral.ai/v1/secrets/workspaces/$WORKSPACE_ID/DATABASE_URL" \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"value": "postgres://..."}'
```

List the secrets in a workspace:

```bash
curl "https://api.mistral.ai/v1/secrets/workspaces/$WORKSPACE_ID" \
  -H "Authorization: Bearer $MISTRAL_API_KEY"
```

:::note
Reading secret values is intended for workloads. Value reads are being restricted to service-account sessions, so standard API keys may not have access.
:::
