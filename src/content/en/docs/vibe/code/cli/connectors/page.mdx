# Connectors

Connectors give the Vibe Code CLI access to **supported first-party and third-party services** from inside a coding session. Unlike [MCP servers](/vibe/code/cli/mcp-servers), which you wire up yourself, Connectors are **Mistral-managed integrations**.

:::info
For the full list of supported connectors and what each one can do, see [Connectors in Vibe Work](/vibe/work/connectors). Vibe Code and Vibe Work share the same integrations.
:::

<SectionTab as="h2" sectionId="vs-mcp">Connectors vs. MCP servers</SectionTab>

Both expose tools to Vibe, but they're operated differently. Pick whichever fits the service you want to connect:

| | Connectors | MCP servers |
|---|---|---|
| **Configured by** | Mistral, as integrated services | You, with `vibe mcp add` or in `config.toml` |
| **Auth model** | Account or service login | OAuth sign-in, headers, environment variables, or API keys |
| **Discoverability** | Curated, listed in the CLI | Anything that speaks MCP |
| **Best for** | Common services with managed integrations | Custom tools, private servers, experimental tools |

<SectionTab as="h2" sectionId="manage">Manage connectors</SectionTab>

Connectors are detected and configured automatically. You can list, enable, disable, and inspect them from inside a CLI session.

List all connectors and MCP servers:

```text
/connectors
```

(`/connectors` is an alias for `/mcp`.)

From the list, with a connector highlighted:

| Key | Action |
|---|---|
| `Enter` | Show the connector's tools, or connect it if it isn't connected. Connectors that need no sign-in, such as DeepWiki, connect directly |
| `e` / `d` | Enable or disable the highlighted connector, or the highlighted tool in the tool list |
| `r` | Refresh the list |
| `/` | Search |
| `Escape` | Go back or close |

Vibe saves these choices to your configuration.

Pass a name to inspect the tools exposed by a specific connector:

```text
/connectors fetch_server
```

If `/connectors` says your API key only gives access to shared connectors, run `vibe --setup` and create a new API key from the link it shows to use your personal connectors.

To turn off connectors entirely, set `enable_connectors = false` in `config.toml`. Your administrator can also block connectors in [admin config](/vibe/code/cli/admin-config#block-connectors).

<SectionTab as="h2" sectionId="stay-in-control">Stay in control</SectionTab>

- **Review what each connector can access** before authenticating.
- **Prefer read-only or scoped access** when the task doesn't need write permissions.
- **Revoke unused connectors** from the relevant service when you no longer need them.
