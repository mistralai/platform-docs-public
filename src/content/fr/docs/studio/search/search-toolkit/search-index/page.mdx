# Index de recherche

Les backends de stockage conservent les fragments traités et permettent de rechercher efficacement dans votre collection de documents. Les stockages vectoriels assurent la recherche sémantique en enregistrant les embeddings des fragments et en trouvant des vecteurs similaires.

<SectionTab as="h2" sectionId="available-vector-stores">Backends disponibles</SectionTab>

### Officiellement pris en charge

| Backend | Usage |
|---------|---------|
| **[Vespa](search-index/vespa)** | Base de données vectorielle avec gestion des schémas, classement, clustering et réplication |
| **[Postgres](search-index/postgres)** | PostgreSQL avec `pgvector` et `pg_textsearch` pour la recherche dense et hybride |

Les deux backends intégrés implémentent le protocole `VectorStoreIndex` et utilisent donc les mêmes interfaces de pipeline d’ingestion et de récupération. Leur provisionnement, leur gestion des schémas et leur gestion du périmètre des requêtes diffèrent. Consultez la page de chaque backend pour plus de détails.

### Communauté

| Backend | Objectif |
|---------|---------|
| **[Qdrant](search-index/qdrant)** | Moteur de recherche vectorielle [Qdrant](https://qdrant.tech/), maintenu sous forme de plugin tiers |

Les backends de la Communauté ne font pas partie du package `mistralai-search-toolkit`. Consultez le dépôt de chaque plugin pour l'installation et l'Assistance.
