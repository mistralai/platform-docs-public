# MCP

The Mistral MCP server connects an AI agent to your Studio workspace over the [Model Context Protocol](https://modelcontextprotocol.io). It exposes your workspace as MCP tools and authenticates each request with your Mistral API key.

Use it from wherever your agent runs: a coding CLI, an IDE, a desktop assistant, or your own application.

| | |
|---|---|
| **Endpoint** | `https://api.mistral.ai/mcp` |
| **Transport** | Streamable HTTP |
| **Authentication** | `Authorization: Bearer <MISTRAL_API_KEY>` |

<SectionTab as="h2" sectionId="before-you-begin">Before you begin</SectionTab>

- A Mistral [API key](/admin/identity-access/api-keys). Keys are workspace-scoped, so the agent gets the access that key already has.
- An MCP client that supports the streamable HTTP transport and static request headers.

Export the key in the environment that launches your client:

```bash
export MISTRAL_API_KEY="your_api_key"
```

<SectionTab as="h2" sectionId="connect">Connect a client</SectionTab>

<ExplorerTabs>
<ExplorerTab value="vibe" label="Vibe Code CLI" default>

```bash
vibe mcp add mistralai \
  --url https://api.mistral.ai/mcp \
  --transport streamable-http \
  --api-key-env MISTRAL_API_KEY
```

This writes the entry to `~/.vibe/config.toml`:

```toml
[[mcp_servers]]
name = "mistralai"
transport = "streamable-http"
url = "https://api.mistral.ai/mcp"

[mcp_servers.auth]
type = "static"
api_key_env = "MISTRAL_API_KEY"
```

The configuration stores the variable name and the environment holds the key. Run `/mcp mistralai` in a session to list the tools. See [MCP servers](/vibe/code/cli/mcp-servers) for permissions and tool filtering.

</ExplorerTab>
<ExplorerTab value="claude-code" label="Claude Code">

```bash
claude mcp add --transport http mistral https://api.mistral.ai/mcp \
  --header 'Authorization: Bearer ${MISTRAL_API_KEY}'
```

Run `/mcp` to check the connection.

</ExplorerTab>
<ExplorerTab value="codex" label="Codex">

```bash
codex mcp add mistral \
  --url https://api.mistral.ai/mcp \
  --bearer-token-env-var MISTRAL_API_KEY
```

This writes the entry to `~/.codex/config.toml`:

```toml
[mcp_servers.mistral]
url = "https://api.mistral.ai/mcp"
bearer_token_env_var = "MISTRAL_API_KEY"
```

Run `codex mcp list` to check the connection.

</ExplorerTab>
<ExplorerTab value="json" label="Other clients">

Clients such as Cursor read a JSON block:

```json
{
  "mcpServers": {
    "mistral": {
      "type": "http",
      "url": "https://api.mistral.ai/mcp",
      "headers": {
        "Authorization": "Bearer ${MISTRAL_API_KEY}"
      }
    }
  }
}
```

Each client has its own config path and its own rules for expanding `${...}`. Check its documentation, then reload the client and open its tool list to check the connection.

</ExplorerTab>
<ExplorerTab value="curl" label="curl">

Probe the endpoint to confirm the key works. The server replies as a server-sent event stream:

```bash
curl https://api.mistral.ai/mcp \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/list",
    "params": {}
  }'
```

</ExplorerTab>
</ExplorerTabs>

<SectionTab as="h2" sectionId="tools">What the server exposes</SectionTab>

The server groups its tools by Studio capability.

| Capability | What an agent can do |
|---|---|
| **[Skills](/getting-started/quickstarts/studio/create-skill)** | Browse the same Skill catalog as Studio, read a Skill and its files, write a new version, change sharing, or delete a Skill. |
| **[Workflows](/studio/workflows/getting-started/overview)** | List workflows, deploy managed workflows, start and signal executions, read events and logs, and manage schedules. |
| **[Connectors](/studio/connectors)** | List your connectors and read the details of each one. |
| **[Observability](/studio/observability/traces)** | Search traces, spans, and logs from your applications, and open a single trace or span. |
| **[Evaluations](/studio/observability/evaluations)** | Manage evaluation projects and evaluations, read runs and records, and follow optimizations. |
| **Organization** | Look up workspace members and resolve a name to a user ID. |
| **Apps** | List your apps, read an app's modules, environments, and running versions, read deploy runs and module or gateway logs, redeploy or roll back a module to a version it already ran, and publish or unpublish an app in the catalog. Env var values are never returned, only their names. |

Observability, Evaluations, and Apps tools appear only for workspaces where those features are turned on. The server lists the tools available to your key, so ask your client for its tool list, or call `tools/list`. Each tool describes its own arguments.

<SectionTab as="h2" sectionId="permissions">Access and permissions</SectionTab>

Every call uses your API key's permissions.

Some tools write. They add Skill versions, change sharing, delete Skills, deploy workflows, start or terminate executions, change schedules, create or delete evaluations, redeploy or roll back app modules, and publish or unpublish apps. Redeploying an app module never ships new code. Use `mistral apps deploy` for that. Configure per-tool approval in your client so you can review those calls before they run.

<SectionTab as="h2" sectionId="troubleshooting">Troubleshooting</SectionTab>

| Problem | Cause | Solution |
|---|---|---|
| `401 {"detail":"Invalid API Key"}` | The key is missing, misspelled, or revoked. | Export the variable in the environment that launches your client, and check the key is active in the console. |
| A tool call returns a permission error. | The operation requires additional workspace access. | Ask a workspace admin for the matching access, then retry. |
| Observability, Evaluations, or Apps tools are missing from the tool list. | The feature is off for your workspace. | Check that the feature is available in Studio, then reconnect the client. |
